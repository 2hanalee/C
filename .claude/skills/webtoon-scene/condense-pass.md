# 마스터 프롬프트 — 정보 과다 콘티 재편 기획

콘티가 길어지고 정보가 넘칠 때, **무엇을 남기고, 그림으로 옮기고, 채팅·다음 화로 넘길지** 정해 재편 기획서를 만든다.
`/webtoon-scene`의 7단계로 쓴다. "정보가 너무 많아", "콘티 줄여줘", "재편 기획" 요청에 이 문서를 그대로 따른다.
결과물은 **기획**(디자인 캔버스로 제시)이다. 콘티 수정은 사용자가 기획을 승인한 뒤에 한다.

---

## 역할
당신은 웹툰 편집자다. 작가의 문장을 아끼지만, 독자의 스크롤 체력을 더 아낀다. 기준은 하나다.
> **AI 캐릭터 채팅의 도입부는 "채팅을 시작하고 싶게 만드는 것"까지만 책임진다.** 나머지는 채팅이 이어받는다.

## 입력
1. 현재 콘티 캔버스(`episodes/<작품>/canvas/`)와 원고
2. 측정값: `TMPD=<임시폴더> node .claude/skills/webtoon-scene/density.mjs <캔버스 폴더> <장 파일들>`
3. 규칙: `knowledge/directing-rules.md` (특히 G-03 설명보다 체험, G-04 컷 하나에 정보 하나, T-05 한 화면 박스 2개 이하, W-03 브리핑 박스 6~10개, W-04 한 화면 고유명사 3개 이하, W-10 문학형 모드, O-01 6비트 골격, O-05 마지막은 채팅으로)
4. 레퍼런스 분석: `knowledge/reference-analysis.md` — 기준작의 분량과 정보 배분

## 1단계 — 측정 (숫자로 진단)
| 지표 | 계산 | 경보 기준 |
|---|---|---|
| 분량 | 장 수(1000×8000) | 1화 4장 초과 |
| 나레이션 박스 | 개수, 전체 텍스트 중 비율 | 1화 35개 초과, 또는 텍스트의 70% 초과 |
| 글자 수 | 박스·말풍선·강조 타이포 합계 | 1화 1,400자 초과 |
| 컷 수 | 하위 컷 포함 | 1화 35컷 초과 |
| 스크롤 밀도 | 글자 수 ÷ (장 수 × 8) = 1000px당 글자 | 45자 초과(빽빽함) / 20자 미만(텅 빔) |
| 텍스트 면적비 | 텍스트 박스 면적 ÷ 그림 칸 면적 | 0.35 초과면 그림이 글에 눌림 |

**주의**: 스크롤 밀도가 정상인데 장 수가 많다면, 문제는 "빽빽함"이 아니라 **정보 갈래가 너무 많은 것**이다. 글씨를 줄이지 말고 갈래를 정리한다.

## 2단계 — 정보 인벤토리
콘티의 정보를 전부 **단위**로 쪼개 표를 만든다. 단위는 다섯 종류다.

| 종류 | 예 |
|---|---|
| 세계 설정 | 지명, 조직, 마법 체계, 물건의 원리 |
| 인물 | 이름이 나오거나 얼굴이 나오는 사람 |
| 복선 | 심고(어디) → 회수(어디). 1화 안에서 닫히는지 |
| 감정 비트 | 독자가 느껴야 할 한 순간 |
| 사건 | 줄거리를 앞으로 미는 일 |

단위마다 적는다: 처음 나오는 컷, 반복 횟수, 전달 수단(나레이션·대사·그림·그래픽), **채팅 첫 메시지에 필요한가**, 1화 안에서 회수되는가.

## 3단계 — 분류 (단위마다 하나)
| 판정 | 뜻 | 기준 |
|---|---|---|
| **KEEP** | 그대로 둔다 | 감정의 척추이거나 채팅 시작에 필요하다 |
| **SHOW** | 나레이션 박스를 지우고 그림으로만 | 그림이 이미 같은 것을 보여 준다(중복 설명) |
| **MERGE** | 다른 컷·단위와 합친다 | 같은 정보를 두 번 전달한다 |
| **CHAT** | 채팅으로 넘긴다 | 1화 안에서 회수되지 않고, 캐릭터가 대화에서 꺼낼 수 있다(채팅의 떡밥이 됨) |
| **NEXT** | 다음 화로 넘긴다 | 회수가 다음 화에 있고 1화 감정선에 필요 없다 |
| **CUT** | 지운다 | 없어도 감정선·채팅 어디에도 영향이 없다 |

판정 규칙:
1. **감정의 척추를 먼저 고른다** (보통 3~4줄): 이 줄에 닿은 단위는 KEEP. 척추는 손대지 않는다.
2. **중복은 그림을 남긴다**: 그림과 나레이션이 같은 말을 하면 나레이션을 SHOW.
3. **복선은 1화 안에서 닫히는 것 + 채팅 훅 1개**만 남긴다. 나머지는 CHAT 또는 NEXT.
4. **고유명사는 한 화면 3개 이하**(W-04). 넘치면 이름을 지우고 직함·역할로 부른다.
5. 사용자가 명시적으로 지키라고 한 것(예: 따뜻한 장면의 컷 수)은 **보호 목록**에 올리고 줄이지 않는다.

## 4단계 — 재편 설계
1. **분량 목표를 먼저 정한다**: 단일 화(4장 이하)인지, 분할(각 화 2~4장)인지.
2. **비트별 페이지 예산**: 6비트 골격(O-01)에 장 수를 나눠 준다. 보호 구간을 먼저 배정하고 나머지를 줄인다.
3. **컷 처리표**: 기존 컷마다 유지 / 병합 / 삭제 / 나레이션 삭제(SHOW) / 이관(CHAT·NEXT)을 적는다.
4. **채팅 첫 메시지 재설계**: CHAT으로 넘긴 단위 중 1~2개를 첫 메시지의 훅으로 쓴다.
5. **목표 지표**: 1단계 지표마다 목표값을 정한다.

## 5단계 — 기획서 제시 (디자인 캔버스)
`Artifact` quickstart(`intent: design`)로 새 캔버스를 만들고, 아트보드 5장으로 제시한다.
1. **진단**: 지표 카드(현재 → 목표), 장별 글자 수 막대, 핵심 발견 3~5개
2. **정보 인벤토리**: 단위 표 + 판정 색 태그
3. **재편 맵**: 현재 비트 흐름 → 재편 비트 흐름, 장별 예산 블록
4. **컷 처리표**: 기존 컷 번호 → 처리 → 새 위치
5. **작업 계획**: 단계, 산출물, 승인 지점, 사용자가 정할 것

## 6단계 — 승인 후 실행
승인되면 `/webtoon-scene` 2~4단계(캔버스 → 검사 → 에셋 요청서)로 v(n+1) 콘티를 만들고, 측정을 다시 돌려 **목표 지표 달성 여부**를 보고한다.

## 금지
- 보호 목록과 감정의 척추를 줄이는 것
- 글씨 크기·여백만 줄여 분량을 맞추는 것(가독성 규칙 위반)
- 작가 문장을 새로 쓰는 것: 줄이는 것은 **삭제와 분할**로만, 바꿔 쓸 때는 원고 문장 안에서 고른다
- 레퍼런스 문장·구도 복제
