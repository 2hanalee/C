### A. 레퍼런스에서 가져올 기능 두 가지 (구현)

A-1. 용어 설명 창
- 대상: 세계관 문서 본문과 메인 「네 장면」, 연표 사건 본문에서 `.kw`로 표시되는 핵심어.
- 동작: 핵심어를 누르면 휴대폰에서는 아래에서 올라오는 판, 넓은 화면(≥640px)에서는 오른쪽 판이 열린다. 판에는 용어 이름, 한두 문장 정의, 「문서 「…」 읽기 →」 링크가 있다. Esc, 바깥 누르기, 닫기 단추로 닫힌다. 닫으면 초점이 누른 용어로 돌아간다.
- 데이터: world.js에 `TERMS` 배열을 새로 둔다. `{ term, def, doc }`. 정의 문장은 이미 공개된 문서 본문에서만 가져온다. 새 설정을 지어내지 않는다. 내부용·기밀 내용은 넣지 않는다.
- 표시: 누를 수 있는 핵심어는 점선 밑줄과 손가락 커서를 단다. 정의가 없는 핵심어는 지금처럼 색만 칠한다.
- 접근성: `button` 요소로 만들고, 판은 `dialog`로 만든다. 기밀 경고창(site.js `buildSheet`)과 같은 방식을 재사용한다.

A-2. 연표 상단 시대 막대
- 휴대폰과 태블릿(<1240px)에서 연표 페이지 위에 얇은 막대를 고정한다. 칸은 ERAS의 시대 이름(이전, 전쟁기, 휴전기)과 사건 수.
- 누르면 그 시대로 부드럽게 이동하고, 스크롤에 따라 지금 보고 있는 시대가 표시된다(IntersectionObserver).
- 넓은 화면은 지금의 왼쪽 목차를 그대로 쓰고 막대는 숨긴다. 사건 종류별 거르기는 만들지 않는다.

A의 완료 기준
- 용어 판이 휴대폰·PC 모두에서 열리고 닫히며, 초점 이동이 맞다.
- 연표 막대가 스크롤과 함께 현재 시대를 정확히 가리킨다.
- 가로 넘침 0, 콘솔 오류 0, 누르는 곳 높이 40px 이상.

### B. 감정·전투 이미지 3:2 대응 (구현)
- 인사기록카드 상세의 사진 칸(`.polaroid .photo`)을 3:2 가로 비율로 바꾼다. 이미지 원본이 3:2이므로 자르지 않는다(`object-fit: cover`여도 잘림이 없어야 한다).
- 표정 단추로 그림을 바꿀 때 칸 크기가 흔들리지 않게 한다.
- 레이아웃: 사진이 가로로 넓어지므로 넓은 화면에서도 사진을 위에, 서식 칸을 아래에 두는 배치와, 지금처럼 왼쪽 사진·오른쪽 서식 배치를 둘 다 시험하고 나은 쪽을 고른다. 고른 이유를 한 줄로 남긴다.
- 목록 카드의 작은 사진(`.rcard .photo`, 세로 3:4)은 두 가지 안을 비교한다.
  - 안 1: 세로 썸네일 유지, `imageFocus`로 얼굴 쪽을 자른다.
  - 안 2: 카드 위쪽에 3:2 가로 사진을 두고 정보는 아래로 내린다.
  - 휴대폰 화면 한 장에 카드가 몇 장 보이는지와 그림 손실을 비교해 권장안을 정하고, 참치에게 확인받기 전에는 안 1을 유지한다.
- 표지 그림과 메인 인물 그림(16:9)은 이번 범위가 아니다.
- 관련 문서를 같이 고친다: characters.js 맨 위 주석(이미지 규격), docs/chatgpt-master-prompt.md와 docs/image-prompts.md의 표정·전투 이미지 비율 항목.

B의 완료 기준
- 3:2 시험 그림(아무 3:2 이미지를 임시로 연결)으로 7개 표정 단추를 눌러도 칸이 흔들리지 않는다. 시험 연결은 커밋하지 않는다.
- 레이나의 지금 그림(16:9, 글자 포함)이 깨지지 않는다.

### C. 설정 변경 문서를 UI에 녹이는 기획안 후보 (기획만, 구현 금지)
1. 문서를 읽고 변경 사항을 표로 정리한다. 열: 번호, 종류(설정 변경 / 새 항목 / 이름 변경 / 삭제 / 구조 변경 / 표현 개선), 내용 요약, 영향받는 데이터 파일, 영향받는 화면, 등급(공개 / 내부용 / 기밀 / ◇ 제외).
2. 지금 사이트와 충돌하는 곳을 따로 뽑는다(사라진 인물, 바뀐 이름, 바뀐 연표 날짜, 깨질 링크).
3. 기획안 후보를 2~3개 만든다. 후보마다 다음을 적는다.
   - 한 줄 콘셉트
   - 정보 구조 변화(페이지·메뉴·구획이 어떻게 달라지는지)
   - 주요 화면 두세 개의 와이어(글로 쓴 배치도면 충분하다)
   - 고치는 파일 목록과 작업량(작음 / 중간 / 큼)
   - 위험과 단점
   - 사용자가 체감하는 변화
   - 후보 사이의 차이가 분명해야 한다. 예: 최소 반영(데이터만 갱신) / 구획 재배치 / 새 화면 추가.
4. 비교표와 권장안 하나, 그리고 참치가 결정해야 할 질문을 3개 이하로 적는다.
5. 결과는 docs/plan-settings-v2.md로 저장하고, 미리 볼 페이지가 필요하면 비공개 아티팩트로 올린다. 구현은 참치가 후보를 고른 뒤에 한다.
