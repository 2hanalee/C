# 인물 「과거」 항목 추가 기획안

작성 11월 14일. 기준 문서: 「마법소녀 세계관 통합 설정집 v3」(rev 229). 구현은 참치가 아래 「정할 것」에 답한 뒤에 한다.

결론: **후보 B(문장 단위 먹칠)를 권한다.** v3의 인물 문단을 한 글자도 바꾸지 않고 인물 상세에 「과거」 구획으로 싣는다. 사이트가 내부용이나 기밀로 가려 둔 사실을 담은 문장은 그 자리에 검은 막대로 가리고, 누르면 지금의 가려진 기록과 같은 규칙으로 열린다. 원문은 그대로 두고 등급 규칙도 깨지지 않는다.

---

## 1. 원문 현황

v3의 인물 항목은 「훅 → 기본 정보 → 인물 문단 → 능력 → 자주 벌어지는 일 → 말투 → 비밀·운용 메모」 순서다(v3 0장). 과거 스토리는 따로 제목이 붙은 칸이 아니라 **인물 문단**에 들어 있다. 인물이 지나온 일(출신, 사건, 상실)과 지금의 습관이 한 문단에 이어진다.

| 항목 | 내용 |
| --- | --- |
| 대상 | 49인 전원. v3 번호와 사이트 `no` 값이 1부터 49까지 그대로 맞는다 |
| 분량 | 인물마다 한 문단, 대략 150~450자, 3~8문장 |
| 사이트 반영 여부 | 없음. 지금 사이트의 「개요」(`summary`)는 v3 문단을 한 문장으로 줄인 사이트용 문장이라 원문이 아니다 |
| ◇ 표시 | 문단 안 문장 끝에 ` ◇` 가 붙은 곳이 많다(예: 레이나 「철거를 미뤄 두었다 ◇.」) |
| 예외 1 | 권도하(25): 「자주 벌어지는 일」 대신 「남은 흔적」 목록 3줄이 있다. 셋 다 과거의 흔적이다 |
| 예외 2 | 문단 안에 `⬛️⬛️` 같은 가림 표기가 있는지 1단계에서 전수 확인한다. 빌리온(44)의 가림 표기는 비밀·운용 메모에만 있고 문단에는 없다 |

## 2. 핵심 문제: 문단과 사이트 등급이 부딪힌다

사이트 규칙은 「한 사실은 사이트 어디에서나 같은 등급이어야 한다. 공개된 곳이 한 군데라도 있으면 공개다」(`characters.js` 머리말)이다. 그런데 v3의 인물 문단에는 사이트가 내부용이나 기밀로 가려 둔 사실이 들어 있다. 11인을 표본으로 읽어 보니 7인이 그렇다.

| 인물 | v3 인물 문단의 문장 | 사이트의 지금 등급 |
| --- | --- | --- |
| 레이나 드 로즈 | 2년 전 지하상가 사건에서 그녀의 판단 착오로 7명이 남았고, 그 책임을 대신 진 선배 신유안이 반역자가 될 때 그녀는 침묵했다. | 기밀 「판단 착오」 |
| 강도윤 | 기숙사 침대 밑 상자에는 정하은의 전투 영상을 담은 USB와, … | 내부 「정하은」 |
| 강세아 | 8년 전 월곶 사건에서 동료 윤새봄과 표나래를 잃었다. / 그날은 방호복 규정이 그녀의 힘을 눌렀다. | 내부 「월곶 하수 터널」, 「체질」 |
| 문보라 | 민간인 구조와 생존자 안정 성과는 최상위지만, … | 내부 「평가」 |
| 메에 | 비건이고, 특히 종이를 좋아한다. | 내부 「식성」 |
| 서리안 | 보육원에서 헤어진 친구 미미를 찾으려고 심야 배달을 시작했다. | 내부 「생활」(그런데 공개 칸인 훅에 「배달 오토바이」가 이미 있다) |
| 권도하 | 문단 7문장 가운데 첫 두 문장을 뺀 다섯 문장 | 내부 1건, 기밀 3건(거짓 맹세, 결투, 예고 장부) |

나머지 4인(유하람, 오윤서, 차유리, 빌리온)은 부딪히는 문장이 없었다. 49인 전체로 넓히면 30인 안팎이 부딪힐 것으로 본다. 그래서 「원문 수정 없이」와 「등급 규칙」을 함께 지키는 방법이 이 기획의 중심이다.

## 3. 후보

### 후보 A. 전부 공개

원문 문단을 그대로 공개 칸에 싣고, 부딪히는 가려진 기록은 공개로 내리거나 지운다.

- 장점: 가장 단순하다. 읽기 흐름이 끊기지 않는다.
- 단점: 가려진 기록 113건 가운데 수십 건이 사라진다. 레이나의 판단 착오, 권도하의 죽음의 진상처럼 열람해야 알 수 있었던 반전이 상세 첫 화면에 그대로 나온다.

### 후보 B. 문장 단위 먹칠 (권장)

원문을 문장 경계에서만 나눠 순서대로 싣는다. 가려야 할 문장은 그 자리에 검은 막대로 덮고, 누르면 열린다.

- 장점: 원문의 글자와 순서가 그대로다. 등급 규칙이 유지된다. 「방위청 인사기록카드, 열람용 사본」이라는 사이트 설정과 맞는다. 먹칠된 사본은 그 자체로 볼거리가 된다.
- 단점: 49인의 문장마다 등급을 매기는 1단계 작업이 필요하다. 문장 안의 일부만 가려야 하는 경우에도 문장 전체를 가린다(문장을 쪼개면 원문을 바꾸는 것이 되므로).

### 후보 C. 통째로 봉인

「과거」 구획 전체를 그 인물의 가장 높은 등급 뒤에 둔다.

- 장점: 구현이 쉽다.
- 단점: 레이나와 권도하는 문단 전체가 기밀 뒤로 가서 공개해도 되는 문장까지 못 본다. 거의 모든 인물의 과거가 한 번 눌러야 보이는 곳에 있어, 대화를 시작하게 하는 사이트의 목적과 어긋난다.

| 기준 | A 전부 공개 | B 문장 먹칠 | C 통째로 봉인 |
| --- | --- | --- | --- |
| 원문 보존 | 지킴 | 지킴(문장 경계에서만 나눔) | 지킴 |
| 등급 규칙 | 가려진 기록 수십 건을 고쳐야 함 | 유지 | 유지 |
| 첫 화면에서 읽히는 양 | 전부 | 공개 문장 전부 | 없음 |
| 작업량 | 작음 | 중간(등급 대조표) | 작음 |
| 화면 재미 | 보통 | 높음 | 낮음 |

## 4. 권장안(B)의 설계

### 4-1. 화면 배치

인물 상세 카드에서 v3 순서를 따라 「개요」 바로 아래, 「능력」 위에 둔다.

```
구분 / 소속 / 직위 / 성격
개요      외국 귀족 가문의 실력주의 아래 자라 …(지금 그대로)
과거      서유럽 한 소공국의 귀족 가문 출신이다. 매달 본가에 랭킹 보고서를
          보내지만, 돌아오는 답장은 늘 한 줄이다. '아직 2위.' 그래서 그녀는 …
          …생일을 챙기는지까지 안다. ███████████████████████████ [기밀]
          ████████████████████. 신유안의 사물함은 지금도 그대로다. …
능력      왕관 없는 정원 …
```

- 문단은 한 덩어리로 이어 쓴다. 문장마다 줄을 바꾸지 않는다.
- 막대 길이는 가린 문장의 길이에 비례한다. 줄이 바뀌면 막대도 다음 줄로 이어진다. 휴대폰 폭(375px)에서도 가로로 넘치지 않는다.
- 막대 끝에 작은 「내부」 또는 「기밀」 꼬리표가 붙는다. 아래 「가려진 기록」의 꼬리표와 같은 모양이다.
- 누르면 지금 규칙 그대로 열린다. 내부는 바로 펼쳐지고, 기밀은 경고창에서 「확인」을 한 번 입력한 뒤로는 바로 열린다.
- 열릴 때 막대가 왼쪽에서 오른쪽으로 걷힌다(0.35초). 움직임 줄이기 설정에서는 바로 바뀐다.
- 가린 문장이 없는 인물(표본에서는 유하람, 오윤서, 차유리, 빌리온)은 문단만 보인다.
- 권도하는 문단 아래에 「남은 흔적」 목록을 원문 그대로 붙이고, 같은 규칙으로 가린다.

### 4-2. 가려진 기록과의 연결

가린 문장은 대부분 아래 「가려진 기록」의 어느 한 건과 같은 사실이다. 둘을 이어서 하나를 열면 다른 하나도 열린 상태가 되게 한다. 「열람 기록 지우기」를 누르면 함께 닫힌다. 이어 줄 기록이 없는 문장만 문장 자체에 등급을 준다.

### 4-3. 데이터

`assets/js/characters.js` 의 인물마다 `past` 배열을 더한다. 항목 하나가 원문의 문장 하나다.

```js
"past": [
  "서유럽 한 소공국의 귀족 가문 출신이다.",
  "매달 본가에 랭킹 보고서를 보내지만, 돌아오는 답장은 늘 한 줄이다.",
  "'아직 2위.'",
  …,
  { "t": "2년 전 지하상가 사건에서 그녀의 판단 착오로 7명이 남았고, 그 책임을 대신 진 선배 신유안이 반역자가 될 때 그녀는 침묵했다.", "ref": "s2" },
  "신유안의 사물함은 지금도 그대로다.",
  "레이나가 학생위원장 권한으로 철거를 미뤄 두었다 ◇."
]
```

- 글자만 있는 항목은 공개 문장이다.
- `ref` 는 같은 인물의 가려진 기록 번호다(`i0` 은 내부용 첫째, `s2` 는 기밀 셋째). 등급은 그 기록을 따른다.
- 이어 줄 기록이 없으면 `"lv": 1`(내부용) 또는 `"lv": 2`(기밀)를 직접 적는다.
- 권도하만 `pastTraces` 배열을 하나 더 둔다. 형식은 같다.

### 4-4. 원문을 바꾸지 않았다는 보증

손으로 옮겨 적지 않는다.

1. Claude Docs 연결로 v3의 49개 인물 문단(와 권도하의 남은 흔적)을 그대로 받아 `docs/v3-past.json` 에 저장한다. 인물 번호, v3 블록 id, 판(rev 229)을 함께 적는다.
2. `tools/qa/build-past.py` 가 문장 경계(마침표, 물음표, 느낌표와 그 뒤의 닫는 따옴표)에서만 나눠 `past` 를 만든다. 등급은 2단계 대조표에서 받은 값만 붙인다.
3. 점검 도구가 인물마다 `past` 문장을 공백 하나로 이어 `docs/v3-past.json` 의 원문과 한 글자까지 같은지 확인한다. 공백, 따옴표, ◇ 하나라도 다르면 실패한다.

v3가 나중에 고쳐지면 1~3을 다시 돌리면 된다. 바뀐 문장만 등급을 다시 매긴다.

### 4-5. ◇ 표시

데이터에는 원문대로 ` ◇` 를 남긴다. 화면에서는 기본으로 숨긴다. 지금 사이트도 ◇를 화면에 내지 않고 데이터 주석(`// ◇`)으로만 관리하기 때문이다. 숨기는 것은 그리는 쪽(렌더러)의 일이라 원문은 그대로다.

### 4-6. 등급을 매기는 기준

문장의 등급은 그 문장이 담은 사실의 사이트 등급을 따른다. 한 문장에 등급이 다른 사실이 섞이면 더 높은 등급으로 가린다.

이미 공개 칸(훅, 개요, 자주 벌어지는 일, 말투)에 나온 사실이 가려진 기록에도 있으면, 규칙상 그 사실은 공개다. 서리안의 심야 배달이 그런 예다. 이런 곳은 문장을 공개로 두고, 겹치는 가려진 기록을 어떻게 할지는 대조표에 따로 올려 참치가 정한다.

## 7. 위험과 대응

- **막대의 누르는 높이.** 글줄 안의 막대는 접근성 점검의 「누르는 곳 높이」 기준(44px)에 못 미칠 수 있다. 막대 위아래로 보이지 않는 누름 영역을 넓히고, 그래도 걸리면 점검 예외로 적는다.
- **문장 나누기의 예외.** 「'아직 2위.'」처럼 따옴표 안에서 끝나는 문장, 말줄임표 등은 나누는 규칙이 틀릴 수 있다. 4-4의 원문 일치 검사가 잡는다.
- **개요와 겹침.** 개요는 v3 문단을 줄인 문장이라 「과거」와 내용이 겹친다. 개요는 목록, 검색, 메인 화면도 쓰므로 그대로 둔다. 상세에서 겹침이 거슬리면 상세에서만 개요를 빼는 안이 있다(정할 것 4).

## 8. 정할 것
